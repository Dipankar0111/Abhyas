Module 1: Foundations of Computer Systems (Lecture 1)

1.1 The Fundamental Nature of a Computer

At its theoretical and practical core, a computer is an electronic machine that processes data according to a stored set of instructions. It operates along the classic IPOS Model:

  • Input: Capturing raw data from the external physical environment (keystrokes, sensor readings, mouse clicks, packets).
  • Process: Manipulating, computing, comparing, and transforming that data according to program logic executed by a central processing unit (CPU).
  • Output: Delivering processed results into human-perceivable or machine-actuable form (screen pixels, radio transmissions, sound, printed sheets).
  • Storage: Retaining instructions and state across immediate or extended periods (volatile RAM and non-volatile SSD/HDD).
The Defining Property: Reprogrammability vs Single-Purpose Tool
An orange juicer crushes oranges: it takes input, applies physical force, and gives juice. Yet it is not a computer. Why? Its behavior is permanently fixed into physical metal and gears.
A digital scale with a microcontroller that weighs crates, receives a firmware update file over USB, and now calculates prices in Rupees and logs past weighings is a computer. Its behavior is dictated by software, and its hardware is general enough to carry out new, distinct sets of instructions without changing physical parts!

1.2 Taxonomy of Modern Computing Machines

Class Primary Purpose Key Characteristics Real-World Example
Embedded System Dedicated, single-purpose automated control Microcontroller, fixed firmware, minimal/no OS, low power, extreme reliability, no user desktop Water-level sensor box bolted to bridge; automobile ABS brakes; smart thermostat
Personal Computer (PC) Interactive general-purpose computing for an individual Desktop/laptop, rich graphical OS (macOS, Windows, Linux), mouse/keyboard/screen, runs diverse user software District office desktop; student laptop; office workstation
Server Serving centralized data and compute over a network to many clients Rack-mounted, headless (no monitor/keyboard attached), optimized for multi-tenant throughput, 24/7 uptime Rack-room machines fielding public flood-alert requests and telemetry database
Supercomputer Massive parallel floating-point mathematical simulations Thousands of interconnected nodes, Petabytes of RAM, liquid cooled, specialized scheduling (SLURM) Atmospheric simulation computing subcontinent weather grids; molecular dynamics; climate modeling

1.3 Failure Analysis: The Hazard of Unused Capability

In the weather department trial, 10 bridges replaced sealed embedded sensor boxes with ordinary Windows laptops. The laptops missed 43 readings, whereas the 190 simple boxes missed only 2. Every laptop failure stemmed from features the sensor task never needed: background Windows updates forcing restarts, power-saving sleep modes suspending the radio, and disk bloat from background logging.

Core Architectural Law: Capability a job never uses is not free. It introduces points of failure, resource contention, and maintenance complexity. A general-purpose machine deployed where an embedded controller belongs is inherently unreliable and inefficient.

Module 2: Hardware Architecture & The Software Spectrum (Lecture 2)

2.1 Compute Engines: CPU vs GPU

Modern computers rely on specialized processing hardware tailored for distinct computational workloads:

  • Central Processing Unit (CPU): The latency-optimized "brain" of the computer. Possesses a few powerful, highly sophisticated cores (typically 4 to 32) engineered to execute complex, sequential branch-heavy code at extremely high clock speeds with deep instruction-level parallelism.
  • Graphics Processing Unit (GPU): The throughput-optimized SIMD (Single Instruction, Multiple Data) engine. Possesses thousands of smaller, simpler cores designed to execute the exact same arithmetic instruction simultaneously across millions of data points (e.g. image pixels, matrix multiplication in neural networks).
Diagnostic Clinic Case Study: The 40-Second vs 26-Minute Scan
Medical scan reconstruction executes identical arithmetic filtering on millions of pixels. The GPU's thousands of lightweight cores perform these operations in parallel in 40 seconds. When the GPU was disabled, the CPU had to perform the operations sequentially through its few cores, taking 26 minutes—even though the CPU itself was fast and healthy!

2.2 Memory and Storage Hierarchy

Layer Technology Speed / Latency Volatility Function in System
CPU Registers & Cache SRAM (L1, L2, L3) Sub-nanosecond to ~10 ns Volatile (Lost on power cut) Immediate instruction and data operands inside CPU die
RAM (Main Memory) DRAM chips ~50 – 100 ns Volatile (Lost on power cut) Holds actively executing program code and live variables
Solid-State Drive (SSD) NAND Flash Memory ~50 – 100 μs (Microseconds) Non-Volatile (Retained permanently) Secondary long-term storage; electronic silicon, high random IOPS
Hard Disk Drive (HDD) Magnetic platters + arm ~5 – 15 ms (Milliseconds) Non-Volatile (Retained permanently) Secondary storage; mechanical spinning platters (slower, fragile)
Critical Speed Order: RAM > SSD > HDD
RAM is thousands of times faster than SSD, and SSD is up to 100 times faster than HDD due to zero mechanical seek time.

2.3 Memory Volatility and Power Cuts: The Unsaved Work Principle

When a user types a document, the active keystrokes and document state are held in RAM. RAM requires continuous electrical charge to maintain its state. When power drops, all capacitor charges in RAM dissipate immediately.

  • Saving a file explicitly copies the buffer from volatile RAM into non-volatile secondary storage (SSD/HDD).
  • Buying 64 GB of RAM does not protect unsaved work from a power outage: RAM loses its contents regardless of capacity. Only persisting to secondary storage guarantees durability.

2.4 Software Classification

  • System Software: Software that provides the underlying platform and manages hardware resources so application software can run.
    • Operating System: Windows, macOS, Linux, Android (manages CPU, RAM, storage, security).
    • Device Drivers: Software adapters allowing the OS to communicate with specific hardware (printers, graphics cards, network cards).
    • Utilities: Antivirus tools, disk formatters, package managers.
  • Application Software: Software created to accomplish specific end-user tasks: Web Browsers (Chrome), Spreadsheets (Excel), Word Processors (Word), Media Players (Spotify).

Module 3 & 4: Commanding the Machine & The Interface Continuum

3.1 Terminal, Shell, and the macOS Transition

The Terminal is an application (a graphical window emulator) that receives keyboard input and displays text output. The Shell is the command-line interpreter running inside the terminal that parses user commands, resolves paths, and executes programs.

  • On modern macOS (macOS Catalina 10.15 and later), the default shell is zsh (Z Shell). Prior to 2019, macOS defaulted to bash (Bourne Again Shell).

3.2 Filesystem Navigation and Path Resolution

  • Root Directory (/): The absolute top of the Unix filesystem hierarchy. Running cd .. at / leaves you at / because the root has no parent directory.
  • Absolute Path: Starts from root (e.g. /bin/ls or /Users/student/docs/file.txt).
  • Relative Path: Starts from the current working directory (e.g. ./script.sh or ../folder/test.py).

3.3 The $PATH Environment Variable

When you type a command like ls, the shell does not inherently know where the binary lives. It scans the colon-separated list of directories stored in the $PATH environment variable (e.g. /usr/local/bin:/usr/bin:/bin:/usr/sbin:/sbin).

What happens if $PATH is empty?
If PATH="", typing ls outputs command not found because the shell cannot search any directory. However, the program still exists on disk! You can run it directly by specifying its absolute path: /bin/ls.
  • which <command>: Prints the full absolute path of the executable resolved via $PATH (e.g. which ls → /bin/ls).
  • pwd: Prints the current working directory path.

3.4 Wildcards & Command Construction

  • *: Wildcard matching zero or more characters. Example: rm -r folder_* will delete folder_1, folder_20, and folder_100.
  • ?: Wildcard matching exactly one character. folder_? only matches single-digit folders like folder_1.
  • | (Pipe): Feeds the standard output of the left command directly into standard input of the right command (e.g. ps aux | grep chrome).

3.5 Interfaces: CLI vs GUI vs API

Module 5: Operating Systems & Process Management (Lecture 5)

5.1 Program vs Process: A Crucial Distinction

  • Program: A passive collection of instructions and static data stored as a file on secondary storage (SSD/HDD). Installed once.
  • Process: An active instance of a program currently loaded into RAM and being executed by the CPU. A process contains an address space, stack, heap, CPU registers, file descriptors, and a unique PID (Process ID).
One Program → Multiple Independent Processes: Launching three separate Google Chrome windows runs three or more distinct processes from the same single executable installed on disk.

5.2 Modern Multi-Process Architecture (Google Chrome Model)

Modern web browsers enforce process isolation: 1 Browser Tab = 1 Child Process.

  • Why not threads or one big process? If one tab crashes due to faulty JavaScript or a memory leak, only that specific child process terminates. The parent browser and all other tabs stay alive!
  • Memory Security: Web tabs execute untrusted code from arbitrary domains. Process isolation prevents one tab from inspecting or altering the memory of online banking in an adjacent tab.

5.3 Virtual Memory and Address Space Isolation

Why cannot Google Chrome read or overwrite data held inside VS Code's memory?

Virtual Address Space Isolation: The Operating System provides every process with its own private virtual address space mapped through hardware page tables. An address inside Chrome has no physical or logical relationship to that same numeric address inside VS Code. Process boundaries are strictly hardware-enforced by the MMU (Memory Management Unit).

5.4 Process Signals: Graceful Exit vs Immediate Termination

Command Signal Behavior Use Case
kill -15 <PID> SIGTERM (Signal 15) Politely requests termination. The process intercepts the signal, closes open file handles, flushes network sockets, writes state, and exits cleanly. Standard orderly shutdown
kill -9 <PID> SIGKILL (Signal 9) Kernel immediately kills the process without notifying it. Cannot be caught, blocked, or ignored. Unsaved state is destroyed. Frozen, uncooperative, or runaway zombie processes

5.5 Out-Of-Memory (OOM) Errors: CPU vs Memory Allocation

When an application under heavy traffic crashes repeatedly with an Out-Of-Memory (OOM) exception:

  • Adding more CPU cores will not fix the crash. CPU cores provide execution throughput; they do not expand memory capacity.
  • The OS memory manager allocates chunks of RAM upon request. When physical RAM and swap space are exhausted, the OS cannot fulfill the request and invokes the OOM killer or throws a fatal memory exception.
  • The correct solution: Increase system RAM or refactor the application to consume less memory.

Module 6: The Unix Filesystem Architecture & Permissions (Lecture 6)

6.1 The Unix Philosophy: "Everything is a File"

In Unix-like operating systems (macOS, Linux), hardware devices, communication channels, and processes are exposed through the standard filesystem interface:

  • /dev/pts/* (Pseudo-Terminals): Terminals appear as files. Running echo "hi" > /dev/pts/2 writes the string "hi" directly onto the screen of terminal 2!
  • /dev/input/*: Mouse and keyboard event streams represented as readable files.
  • /tmp: Temporary workspace for transient files. Automatically wiped clean on system reboot!
  • /bin: Essential system binary executables needed for single-user mode and booting.
  • /etc: Host-specific system-wide configuration files.

6.2 File Permission Triplets and Octal Calculation

Running ls -l displays a 10-character string such as -rw-r--r--:

-  r w -  r - -  r - -
^  [Owner] [Group] [Others]
Type: (-) Regular file, (d) Directory
Permission Symbol Numeric (Octal) Value Meaning on Files Meaning on Directories
Read r 4 View file content List contents (run ls)
Write w 2 Modify / truncate file Create / delete files in dir
Execute x 1 Run file as a program Enter / cd into directory

Master Permission Matrix & Key Values

  • chmod 644 (-rw-r--r--): Owner has Read + Write (4+2=6); Group has Read (4); Others have Read (4). Standard permission for text files, web pages, and public documents.
  • chmod 600 (-rw-------): Owner has Read + Write (4+2=6); Group has None (0); Others have None (0). Strict privacy for SSH private keys and personal notes.
  • chmod 754 (-rwxr-xr--): Owner has Read + Write + Execute (4+2+1=7); Group has Read + Execute (4+1=5); Others have Read (4).
  • chmod 755 (-rwxr-xr-x): Owner has Read + Write + Execute (7); Group and Others have Read + Execute (5). Standard for executable scripts and directories.
  • chmod 777 (-rwxrwxrwx): Full permissions for everyone. Extremely dangerous anti-pattern. Grants write and execute access to any arbitrary user on the machine.

6.3 Execution Metadata vs File Extensions

  • On Windows, a file's executable status is tied to its extension (.exe, .bat).
  • On Unix/Linux/macOS, execution is determined strictly by the execute bit (x) stored in file metadata.
  • A file named hello.txt made executable via chmod +x hello.txt and renamed to run_me.banana will execute cleanly with ./run_me.banana because the metadata bit persists across renames!
  • Why newly created files lack execute permission: Security safeguard to prevent unvetted downloaded scripts from accidentally running.

Module 7 & 8: Software Execution & Low-Level Data Representation

7.1 Software Execution Pipeline: Compilers vs Interpreters

The CPU understands only binary machine code. Every programming language must eventually resolve to machine code:

  • Compiled Languages (C, C++, Rust, Go): An Ahead-Of-Time (AOT) compiler reads source code, optimizes it, and emits a standalone binary machine code file tailored directly for the target CPU architecture. Ultra-fast execution, zero runtime interpreter overhead.
  • Interpreted Languages (Python, Ruby, JavaScript): Source code is executed via an interpreter program (e.g. /usr/bin/python3). When you run python3 hello.py, two programs are involved: the Python interpreter binary and your script. The interpreter parses code and evaluates it dynamically. Portable, but slower than compiled code.
  • Just-In-Time (JIT) Compilation: Hybrid approach (e.g. PyPy, Java HotSpot, V8) that compiles frequently executed bytecode loops into native machine code at runtime.

7.2 Low-Level Data Representation: Bits, Bytes, and Hex

  • Bit: The fundamental binary unit (0 or 1), physically represented by electrical voltage levels (high vs low).
  • Byte: 8 bits. Represents $2^8 = 256$ distinct values (0 to 255 unsigned, or -128 to +127 signed).
  • Hexadecimal (Base-16): Uses digits 0-9 and letters A-F (where A=10, B=11, C=12, D=13, E=14, F=15).
    • 1 Hex digit = 4 binary bits (1 Nibble). E.g., binary 1111 = Hex F.
    • 1 Byte = Exactly 2 Hex digits. E.g., binary 11111111 = Hex FF (decimal 255).

7.3 Text Encodings: ASCII vs Unicode UTF-8

  • ASCII: 7-bit standard (128 characters) covering standard English alphabet (A-Z, a-z, 0-9, punctuation, control codes). E.g., 'A' is 65 (binary 01000001).
  • Unicode (UTF-8): Variable-length encoding (1 to 4 bytes) that represents over 150,000 characters spanning all human languages, mathematical symbols, and emoji. Backward-compatible with ASCII in its first 128 code points.

7.4 Image Representation & File Signatures

  • RGB Image: Each pixel is composed of 3 bytes: Red (0-255), Green (0-255), Blue (0-255).
  • RGBA Image: Adds an Alpha transparency channel (4 bytes per pixel).
  • Uncompressed Image Size: $ ext{Size (bytes)} = ext{Width} imes ext{Height} imes ext{Channels}$. A $1920 imes 1080$ RGB image uncompressed requires $pprox 6.22 ext{ MB}$.
  • Magic Numbers (File Signatures): Unique byte sequences at the beginning of files that identify their format (e.g., PNG files start with bytes 89 50 4E 47 0D 0A 1A 0A).
  • Encoding vs Encryption: Encoding converts data into standard formats for interoperability (public algorithm, easily reversed without a key). Encryption scrambles data using mathematical ciphers and secret keys to enforce confidentiality.

Module 9 & 10: Version Control Systems — Git & GitHub (Lectures 9 & 10)

9.1 The Git Architecture: The Three Trees

Git is a distributed version control system that runs entirely on your local machine inside a hidden .git repository directory:

[ Working Directory ]  --- git add --->  [ Staging Area (Index) ]  --- git commit --->  [ Local Repository (.git) ]
(Actual modified files)                   (Snapshot prepared for commit)                 (Permanent immutable history)
  • Working Directory: The active filesystem folder where you edit files. Files can be untracked or modified.
  • Staging Area (Index): The intermediate staging buffer where changes are selected and reviewed prior to recording.
  • Local Repository (Commit History): The cryptographically verified Directed Acyclic Graph (DAG) of commit snapshots stored inside .git.

9.2 Git vs GitHub: Local Tool vs Remote Hub

Dimension Git GitHub
Nature Command-line Version Control tool Cloud hosting platform & collaboration hub
Location Installed locally on your personal machine Hosted on cloud servers (github.com)
Function Tracks file changes, commits, branches locally Coordinates team sharing, Pull Requests, code reviews, CI/CD
Internet Functions 100% offline without network Requires internet connectivity to push/pull/browse

9.3 The Core Collaboration Workflow

  1. Initialize & Configure: 
    git config --global user.name "Your Name"
git config --global user.email "you@example.com"
git init
  2. Stage & Commit Changes: 
    git status                # Check working tree status
git add notes.txt         # Move file to Staging Area
git commit -m "feat: add initial notes"  # Commit to local repo
  3. Connect to Remote GitHub Repository: 
    git remote add origin https://github.com/username/repo.git
git branch -M main
git push -u origin main   # Send commit history to GitHub
  4. Team Collaboration & Pull Requests: 
    git clone https://github.com/org/repo.git   # Download full repo
git switch -c feature-branch                # Create and switch to new branch
git push origin feature-branch              # Push branch to remote
# Open a Pull Request (PR) on GitHub for code review, then Merge into main!
